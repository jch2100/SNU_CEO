# 우리 회사 인사이트 허브 만들기 — 설치와 사용

기업 자료를 이해하고, 회사 맞춤 조사와 실제 클라우드 예약을 검증한 뒤 직원용 사내 웹페이지를 만드는 스킬입니다. 앞으로 기능을 추가할 수 있는 공간을 목표로 하되, 첫 기능은 트렌드·인사이트 공유입니다.

## 준비

- `company-insight-hub.zip`을 내려받아 회사 자료가 있는 작업 폴더에 넣습니다. 폴더 이름은 자유입니다.
- 기존 기업 소개, 제품·서비스 자료, 이전 보고서 등을 준비합니다. 한 문장 메모나 새 보고서는 필요 없습니다. 디자인 참고 화면이 있으면 함께 넣습니다.
- 설치에는 공개 플러그인 등록·개발자 모드·별도 MCP 서버가 필요하지 않습니다. 다만 스킬 설치와 실제 서비스 이용 권한은 다릅니다. Codex 사용 가능 여부, 웹 검색, Sites, 클라우드 예약과 연결 권한은 각 계정에서 확인합니다. 무료 계정에서 전체 과정이 된다는 보장은 없습니다.
- 민감정보를 포함한 자료는 공유 가능한 사본으로 준비하는 편이 좋습니다. 분석용 자료를 넣었다고 그 내용을 게시하도록 허락한 것은 아닙니다.

## 1. 설치 요청

Codex에서 자료 폴더를 선택하고 다음 요청을 보냅니다.

```text
이 폴더의 company-insight-hub.zip을 확인해 주세요.
압축 안의 파일 목록과 스킬 내용을 먼저 살펴보고,
현재 Codex가 인식하는 사용자용 스킬 위치에 설치해 주세요.
기존에 같은 이름이 있으면 변경 내용을 설명하고 덮어쓰기 전에 물어봐 주세요.
설치한 위치와 스킬 이름을 알려 주세요. 아직 프로젝트는 시작하지 마세요.
```

ZIP을 채팅에 첨부하거나 자료 폴더에 두는 것만으로 자동 설치되지는 않습니다. 파일 업로드만 가능한 환경은 로컬 파일 설치를 지원하는 Codex 환경과 다를 수 있습니다.

설치하는 AI를 위한 참고: 공식 문서의 사용자 스킬 위치는 `~/.agents/skills/<skill-name>/SKILL.md`입니다. 기존 Codex 환경이 다른 인식 위치를 쓰고 있으면 실제 설정과 발견 결과를 확인합니다. Windows 사용자 폴더 이름을 강사의 경로로 고정하지 않습니다. 원본 ZIP은 보존하고, ZIP의 상위 폴더가 중복되어 `company-insight-hub/company-insight-hub/SKILL.md`가 되지 않도록 합니다. 압축 경로가 설치 폴더 밖으로 나가는 파일을 허용하지 않습니다.

## 2. 설치 확인

- AI가 스킬 이름 `company-insight-hub`와 실제 설치 위치를 알려 주는지 확인합니다.
- 현재 ChatGPT 데스크톱 앱에서는 새 대화의 입력창에 `@`를 입력하고, 목록에서 **우리 회사 인사이트 허브 만들기** 또는 **company-insight-hub**를 선택합니다. 단순히 이름을 타이핑하는 것과 목록에서 선택하는 것을 구분합니다.
- 목록에 안 보이면 설치 위치와 인식 상태를 확인하고, “설치된 company-insight-hub 스킬을 읽고 사용해 주세요”라고 요청할 수 있습니다. 이것은 목록 표시 확인을 대신하지 않습니다.
- 첫 응답에서 자료를 읽고 프로젝트의 AGENTS.md와 PLAN.md를 작성하며 회사와 목적을 질문하는지 봅니다. 곧바로 사이트를 배포하거나 예약을 등록하면 중단하고 현재 단계를 확인합니다.
- 목록이 갱신되지 않으면 앱을 다시 열고 새 대화에서 확인합니다. 파일의 형식 검사 통과와 실제 호출 확인을 구분합니다.

## 3. 시작 요청

```text
선택한 ‘우리 회사 인사이트 허브 만들기’ 스킬을 사용해 주세요.
선택된 폴더의 기업 자료를 바탕으로, CEO와 전 직원이 함께 사용할
확장 가능한 사내 웹페이지를 만들고 싶습니다.
첫 기능은 우리 회사 맞춤 트렌드·인사이트 공유입니다.
먼저 자료를 읽고 제가 원하는 것을 질문하며 구체화해 주세요.
```

## 4. 내가 할 일

| 단계 | 내가 할 일 | 다음 단계로 넘어가기 전에 볼 것 |
|---|---|---|
| 1. 기업 맞춤 인사이트 | 회사 목표·현재 과제를 설명하고 질문에 답합니다. 조사 결과에서 유용하거나 불필요한 것을 말합니다. | 우리 회사에 중요한 이유가 있는가? 직원들의 판단에 도움이 되는가? 근거를 볼 수 있는가? |
| 2. 실제 예약 시험 | 요일·조사 시작 시각·시간대를 정하고 필요한 계정 연결을 직접 승인합니다. 일회 시험 예약에 동의합니다. | 진짜 클라우드 실행 기록과 새 결과가 있는가? 내용과 기간이 맞는가? |
| 3. 직원용 웹페이지 | 읽는 상황, 첫 화면, 디자인과 공유 범위를 선택합니다. 직접 읽고 눌러 보며 수정점을 말합니다. | 예약 결과가 DB와 화면에 쌓이는가? 지난 기록·원문·모바일·접근 범위가 맞는가? |

“좋아요”라고 말할 때 무엇을 승인하는지 함께 말하면 분명합니다. 예: “이 조사 기준과 결과를 확인했습니다. 2단계로 진행해 주세요.” 예약이나 게시 범위는 해당 작업을 하기 전에 확인합니다. 원하지 않는 기능은 추가하지 않아도 됩니다.

예약 도구가 게시된 Sites를 먼저 요구하면 AI가 선택지를 설명합니다. 최소 비공개 운영 기반을 먼저 준비할지, 검증 순서를 조정할지 선택한 뒤 진행합니다. 이 제약을 숨기고 사이트를 먼저 만드는 것은 정상 흐름이 아닙니다.

## 5. 다음에 이어가기

입력창에서 `@`로 스킬을 선택한 뒤 다음 요청을 보냅니다. Codex CLI·IDE에서 사용하는 `$` 표기와 혼동하지 마세요.

```text
선택한 스킬을 사용해 이 프로젝트의 AGENTS.md와 PLAN.md,
현재 결과를 읽고 마지막으로 확인한 단계부터 이어가 주세요.
이미 있는 사이트와 예약을 중복해서 만들지 마세요.
```

AGENTS.md는 작업 규칙, PLAN.md는 회사별 결정과 진행 상태입니다. 설치한 스킬은 공통 진행 방법입니다. 파일들을 같은 용도로 취급하지 않습니다.

## 연결이 막히면

오류 문구를 남기고 어느 연결이 필요한지 설명을 요청합니다. 비밀번호·API 키를 대화에 붙여 넣지 않습니다. 예약 등록과 실제 실행을 구분하고, 못 본 실행은 미검증으로 둡니다. 강사의 성공 사례가 모든 계정에서의 작동을 증명하지는 않습니다.

참고: [OpenAI 스킬 안내](https://learn.chatgpt.com/docs/build-skills). 배포 파일은 절차를 안내하며, 서비스 구독·연결·인증을 제공하지 않습니다.
