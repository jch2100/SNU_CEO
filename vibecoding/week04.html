실행 전 확인 · 5분

받은 코드를 확인한 뒤 엽니다

  1. 받은 폴더를 Codex로 열고 아래 요청을 입력합니다. 도구 코드만 확인하게 하고 회사 자료는 주지 않습니다.
  2. HTML 파일 맨 위에서 Content-Security-Policy 선언을 찾아봅니다. 이 화면의 외부 연결을 제한하는 줄입니다. 줄이 지워졌다면 사용을 멈추고 강사에게 보여 주세요.
  3. 와이파이를 끄고 HTML 파일을 더블클릭해 엽니다. 유선 인터넷 등 다른 연결이 남아 있으면 와이파이만 꺼도 오프라인이 되지는 않습니다. 연결 상태를 확인하세요.
README의 실행 전 확인 요청
개인정보_가림도구.html이 인터넷으로 무언가를 보내거나 받아 오는 부분이 있는지 확인해 줘.

화면이 열리는지 확인한 뒤 다음 단계의 체크·전환·복원도 연결을 끈 상태에서 시험해 보세요. AI에 가린 사본으로 일을 시킬 때는 인터넷을 다시 연결합니다. 도구의 연결 제한 선언은 그대로 둡니다.

코드 검토 답변과 선언 한 줄만으로 모든 위험이 없어지는 것은 아닙니다. 내 PC에서 실제로 작동하는지도 확인합니다. 오프라인 실행과 엣지 동작은 아직 사전 확인을 마치지 못한 항목입니다. 동작하지 않으면 환경과 오류를 기록하고 강사에게 보여 주세요.

한 바퀴 돌려 보기 · 10분

가린 사본으로 일하고, 결과를 되돌립니다

처음 열면 암호를 정합니다. 수업에서는 강사가 안내한 공통 연습용 암호를 씁니다. 실제 사용 때 그대로 쓰지 마세요. 암호를 잊으면 바꾼 기록을 열 수 없고, 그 기록을 이용한 복원도 할 수 없습니다.

순서지금 할 일직접 확인할 것
1 · 자료 넣기연습자료/고객명단.csv를 넣습니다. 이름 열과 후보 건수를 봅니다.검사한 파일이 가상 연습자료인가?
2 · 번호로 바꾸기번호로 바꾼 사본을 내려받아 열어 봅니다. 원본은 그대로 둡니다.이름·연락처가 바뀌었는가? 줄 수 11, 금액 합계 55,000이 유지되는가?
3 · AI에 일 시키기인터넷을 다시 연결합니다. 확인한 사본만 AI에 주고, 금액을 기준으로 정리한 CSV를 돌려달라고 말합니다.첨부한 것이 원본이 아닌가? 아래 번호 유지 문장을 덧붙였는가?
4 · 원상 복귀AI 결과를 CSV로 받아 도구의 원상 복귀에 넣습니다. 복원된 결과를 내려받습니다.번호가 원래 정보로 돌아오는가? AI의 정리 결과와 금액은 유지되는가?
AI 작업 요청에 덧붙일 문장 · README
고객_0001 같은 번호는 모양을 바꾸지 말고 그대로 써 줘

이어서 놓친 것을 찾습니다. 고객명단을 먼저 전환한 상태에서 연습자료/상담메모.txt를 넣어 보세요. 가상 이름인 박서연·최민준은 찾지만 한지우는 놓치는지 직접 확인합니다. 남아 있는 이름은 사람이 읽어 찾아야 합니다. 이 메모를 그대로 AI에 보내지 않습니다. 제품소개.txt는 후보 없음으로 나오는지도 확인하세요.

가림 도구에서 내보내 AI에 올리고, AI 결과를 내려받아 다시 넣습니다. 올리고 내려받는 번거로움이 있습니다. 그 번거로움이 안전장치입니다. 파일을 건넬 때마다 내가 확인하는 지점이 생깁니다.

바꾼 기록은 원래 정보와 번호의 짝 목록입니다. 암호로 잠겨 이 컴퓨터의 이 브라우저에 저장됩니다. 브라우저 저장정보를 지우거나 기기·브라우저를 바꾸기 전에는 기록을 내보내고, 같은 암호로 다시 열 수 있는지 확인하세요. 기록과 암호는 회사 기준에 따라 관리하고 AI에 올리지 않습니다.

줄 수·합계와 기본 전환·복원은 설계 문서의 2026-11-10 크롬 자동 시험에서 확인한 기준입니다. 이 표는 내 PC에서도 그렇게 되는지 확인하기 위한 것입니다. 버튼 누르기·끌어놓기·폴더 선택까지 모든 환경에서 확인됐다는 뜻은 아닙니다.

우리 회사 것으로 고치기 · 10분

이름, 규칙 세 줄, 번호 형식 하나를 바꿉니다

받은 원본을 보관하고 수정용 사본을 준비합니다. 회사 이름, 지킬 규칙 세 줄, 사번 또는 고객번호 형식 하나를 정하세요. 번호는 실제 값 대신 형식만 알려 줍니다. 아래는 저장소 README의 요청문 그대로입니다. 대괄호 부분만 내 상황에 맞게 채워 Codex에 입력합니다.

README 원문 · 우리 회사 것으로 고치기
개인정보_가림도구.html 맨 위의 "회사에 맞게 고치는 곳"만 수정해 주세요. 다른 부분은 건드리지 마세요.
1. COMPANY를 "[우리 회사 이름] · AI에 넣기 전 가림 도구"로 바꿔 주세요.
2. RULES 세 줄을 다음으로 바꿔 주세요: [규칙 1] / [규칙 2] / [규칙 3]
3. PATTERNS에 우리 회사 [사번 / 고객번호] 형식을 한 줄 추가해 주세요. 형식 예: [예: EMP-12345]
인터넷 연결이 필요한 것은 넣지 마세요. 고친 뒤 연습자료 폴더의 파일로 체크·전환·복원이 그대로 되는지 확인하는 방법을 알려 주세요.

수정한 파일을 다시 열어 회사 이름과 세 줄이 바뀌었는지 봅니다. 추가한 번호 형식은 저장소 가상 자료의 사본에서만 시험하세요. 같은 연습자료로 체크·전환·복원을 다시 수행하고, 인터넷 연결 제한 선언도 남아 있는지 확인합니다.

10분은 수업 배정 시간입니다. 그 안에 고치고 검증할 수 있는지는 아직 리허설 전입니다. 막히면 받은 원본으로 돌아가고, 수정한 부분과 오류를 남겨 도움을 받으세요. 바뀐 화면만 보고 성공했다고 판단하지 않습니다.

보관과 다음 행동 · 5분

만드는 곳과 쓰는 곳을 나눕니다

코드 수정이 끝났으면 도구 화면의 보안 규칙과 다음에 할 일 여섯 단계를 읽습니다. 고친 도구를 AI 작업 폴더 밖의 사용 위치로 옮기세요. 원본 자료와 바꾼 기록도 AI가 읽는 작업 범위 밖에 둡니다. AI에는 확인한 작업용 사본만 전달합니다.

위치둘 것확인할 것
AI 밖의 사용·보관 위치가림 도구, 원본, 복원용 기록회사 승인 위치인가? AI 접근과 동기화·공유 설정은 어떤가?
AI 작업 폴더직접 확인한 가린 사본, AI 작업 결과원본·복원 기록·불필요한 자료가 섞이지 않았는가?

폴더 위치는 출발점입니다. 이름을 바꾸거나 C드라이브에 둔다고 접근이 차단되지는 않습니다. 회사가 정한 보관소를 우선하고, AI의 실제 접근 범위와 공유 설정을 확인하세요. 회사 적용 전에는 규칙을 확인할 담당자도 정합니다.

이 도구로 지킬 수 없는 것도 확인합니다

  • 찾은 것만 바꿉니다. 처음 보는 이름, 주소, 단가·계약 조건 같은 영업비밀은 놓칩니다. 후보가 0건이어도 안전 판정은 아닙니다.
  • 해킹, 악성 프로그램, 내부자 반출, 우리가 만든 웹사이트의 허점은 막지 못합니다.
  • 원본이 AI 작업 폴더에 남아 AI가 읽을 수 있으면 가린 사본만 따로 만드는 취지가 무너집니다.
  • 이름을 번호로 바꾼 자료도 개인정보인 가명정보로 다룹니다. 어떤 AI에든 보내도 된다는 뜻이 아니며, 회사의 자료 처리 기준과 허용 환경을 먼저 확인합니다.
  • 회사 전체의 정보유출방지 제품과 운영은 전산 담당자의 영역입니다. 오늘 실습은 그 일의 작은 한 조각을 경험하는 첫 번째 안전장치입니다.
  • CSV·TXT·MD만 읽습니다. 한글·엑셀·PDF는 검사 못 함입니다. 같은 이름의 두 사람은 같은 번호가 될 수 있으므로 결과를 확인해야 합니다.

실제 회사 자료 적용은 수업 뒤 과제입니다. 회사 기준을 확인하기 전에는 실제 원문을 Codex나 외부 AI에 보내지 마세요. 본문 실습은 끝까지 저장소의 가상 자료만 사용합니다.

내 환경에서 발견한 문제 → 실제로 바꾼 것 → 다시 확인한 결과를 말해 보세요. 도구가 놓친 값, 바꾼 규칙이나 보관 위치, 재시험 결과를 각각 하나씩 남기면 됩니다.

실습 이후

회사에서 먼저 할 보안 점검을 하나 정합니다

  • 회사 기준 확인하기. 어떤 자료를 어떤 AI에 넣을 수 있는지 확인하고, 애매할 때 물어볼 담당자를 알아둡니다.
  • 원본과 복원 기록의 위치 확인하기. 어디에 저장돼 있고 AI 작업 폴더나 연결된 앱에서 그 위치를 읽을 수 있는지 봅니다.
  • 보내기 전 사본과 공유 링크 확인하기. 가린 사본에 이름·연락처·계약 조건이 남았는지 직접 읽어 봅니다. 이미 공유한 자료가 있다면 링크를 누가 열 수 있는지도 확인합니다.

예를 들어 “이번 주에 고객명단 원본이 AI 작업 폴더에 있는지 확인하겠습니다”처럼, 먼저 할 일 하나를 적어 보세요.
